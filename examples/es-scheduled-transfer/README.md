# Ejemplo: transferencia programada recurrente (ficticio)

Insumos y resultado esperado para probar story-forge sin datos reales. Banco, textos, tickets y servicios son inventados. Versión en inglés: [`../en-scheduled-transfer/`](../en-scheduled-transfer/).

- `requirement.md`: requerimiento como estaría en la wiki.
- `design-summary.md`: resumen del diseño como lo produce sf-design-reader.
- `expected-story.md`: historia esperada completa.
- `../evaluation-checklist.md`: lista de "pasa / no pasa" para comparar.

Pide "escribe la historia AND-101 con estos insumos" (perfil de ejemplo `profiles/examples/banco-andino.es.profile.yaml`) y compara el resultado con `expected-story.md` usando la lista de evaluación.
